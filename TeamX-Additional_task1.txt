1. 동시 등록 시 ID 충돌

원인

그룹 생성(04번)과 논문 생성(08번)에서 MAX(ID) + 1로 새 ID를 계산함.
두 요청이 동시에 같은 최대값을 읽으면 같은 ID를 사용해 한쪽 등록이 기본키 중복 오류(ORA-00001)로 실패함.

해결

Oracle의 SEQUENCE를 사용하여 해결함.
그룹, 논문, 그룹 논문 연결의 ID를 각각 study_group_seq.NEXTVAL, paper_seq.NEXTVAL, group_paper_seq.NEXTVAL로 발급하도록 변경.


2. 논문별 번호(하이라이트·댓글) 동시 발급 시 충돌

원인

하이라이트 생성(12번)과 댓글 작성(14번)에서 번호를 MAX(번호) + 1로 계산함.
하이라이트·댓글 번호는 논문(group_paper_id)마다 1번부터 매기는 값이라 시퀀스로 발급할 수 없음.
같은 논문에 두 요청이 동시에 들어오면 같은 최대값을 읽어 같은 번호를 사용하고, 한쪽이 기본키 중복 오류(ORA-00001)로 실패함.

해결

setAutoCommit(false)로 트랜잭션을 시작한 뒤, 해당 논문의 GROUP_PAPER 행을 SELECT ... FOR UPDATE로 잠금.
잠근 상태에서 MAX(번호) + 1을 계산하고 INSERT한 뒤 commit하여 잠금을 해제함. 실패 시 rollback.
같은 논문에 대한 다른 요청은 앞 트랜잭션이 끝날 때까지 대기한 뒤 최신 최대값을 읽으므로 번호가 겹치지 않음.

확인 방법

DB 콘솔에서 SELECT * FROM GROUP_PAPER WHERE group_paper_id = 16 FOR UPDATE를 실행하고 커밋하지 않은 상태로 웹에서 같은 논문에 하이라이트를 생성함.
웹 요청이 대기 상태로 멈추고, 콘솔에서 rollback하는 즉시 다음 번호로 생성되는 것을 확인함.


3. 부모 댓글 확인과 답글 작성·댓글 삭제 사이의 경쟁 (TOCTOU)

원인

댓글 작성(14번)은 하이라이트·부모 댓글이 존재하는지 확인한 뒤 INSERT하고, 댓글 삭제(16번)는 답글 수를 확인한 뒤 삭제함.
확인과 변경 사이에 다른 요청이 끼어들면 삭제된 댓글에 답글이 달리거나, 답글이 생긴 댓글을 삭제하려다 참조 무결성 오류가 발생할 수 있음.

해결

댓글 작성과 댓글 삭제 모두 트랜잭션 시작 직후 같은 GROUP_PAPER 행을 FOR UPDATE로 잠금.
존재 여부·답글 수 확인과 실제 INSERT/DELETE를 같은 트랜잭션 안에서 처리함.
같은 논문에서는 댓글 작성과 삭제가 한 번에 하나씩만 실행되므로 확인한 결과가 변경 시점까지 유지됨.


4. 댓글 삭제 작업의 부분 반영 (원자성)

원인

댓글 삭제(16번)는 본인 확인, 답글 수 확인, 삭제 또는 '삭제된 댓글' 처리, 남은 답글이 없는 부모 댓글 정리까지 여러 SQL로 이루어짐.
자동 커밋 상태에서는 SQL마다 따로 반영되어, 중간에 오류가 나면 일부만 반영된 상태가 남을 수 있음.

해결

setAutoCommit(false)로 전체 과정을 하나의 트랜잭션으로 묶고, 모든 작업이 끝난 뒤 한 번만 commit함.
중간에 예외가 발생하면 rollback하여 처음 상태로 되돌림.


5. 동시 수정 시 변경 내용 손실 (Lost Update)

원인

그룹 메모·상태 수정(11번)과 댓글 수정(15번)에서 두 사용자가 같은 화면을 열고 각자 저장하면,
나중에 저장한 쪽이 먼저 저장한 내용을 알지 못한 채 덮어씀.

해결

낙관적 동시성 제어(버전 비교) 방식을 사용함.
수정 화면을 열 때 현재 버전을 hidden 값으로 함께 전달하고, 저장 시 UPDATE ... WHERE 버전 = (열었을 때 버전) 조건으로 갱신함.
그 사이 다른 사용자가 먼저 수정했다면 갱신되는 행이 0개가 되므로, "다른 사용자가 먼저 수정했다"는 안내와 함께 최신 내용을 다시 보여 줌.
- 그룹 메모·상태: GROUP_PAPER에 수정 시각 컬럼이 없어 TO_CHAR(ORA_HASH(notes)) || ':' || status를 버전으로 사용
- 댓글: TO_CHAR(NVL(updated_at, created_at), 'YYYYMMDDHH24MISSFF6')를 버전으로 사용
버전 값은 저장 시점에 DB에서 다시 계산하여 비교하므로 스키마 변경 없이 적용함.

확인 방법

같은 수정 화면을 두 탭에서 열고, 한 탭에서 먼저 저장한 뒤 다른 탭에서 저장하면 덮어쓰지 않고 충돌 안내가 표시되는 것을 확인함.


6. 같은 논문·태그 동시 추가 시 중복

원인

그룹에 논문 추가(09번)와 논문에 태그 추가(10번)에서 두 사용자가 같은 항목을 동시에 추가하면 중복 삽입이 시도됨.

해결

GROUP_PAPER의 UNIQUE(group_id, paper_id)와 PAPER_TAG의 PRIMARY KEY(paper_id, tag_id) 제약으로 DB에서 중복을 차단함.
존재 여부를 먼저 조회한 뒤 삽입하는 대신 DB 제약에 판단을 맡겨 확인과 삽입 사이의 틈을 없앰.
중복으로 ORA-00001(오류 코드 1)이 발생하면 오류 화면 대신 "이미 등록된 항목"이라는 안내 메시지를 표시함.
또한 그룹 논문 추가(09번)의 group_paper_id도 1번 항목의 group_paper_seq.NEXTVAL로 발급하도록 변경함.
